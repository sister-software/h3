## Evidence

- C reference: pinned `24946ad1` (`v4.5.0-67-g24946ad1`), re-fetched 2026-11-02 with no newer
  upstream commits; CTest 325/325. Fixtures: 37,539 cases in 71 files, regenerated byte-identically.
- Native: 41 Rust tests (parity suites for every phase, unit tests, crate doctest).
- JavaScript: 180 Vitest tests, including C parity over every JavaScript-expressible fixture
  (34,805 cases), the init state machine, resource limits, the argument and error contract, and
  h3-js migration (every difference on the fixtures belongs to a documented category).
- Initialization (operator decision, 2026-11-02): no `init` is required. The first H3 call
  instantiates synchronously from the embedded binary (default entry) or the package's own
  `h3.wasm` (`workerd` export condition); `init` remains optional for preloading, limits, or a custom
  binary. Measured basis: synchronous compile and instantiate allowed in Node, Chromium 156 and
  Firefox 157 main threads, and workerd for a bundled module. WebKit/Safari is unverified (its
  Playwright build cannot launch on this host without system packages).
- Runtimes (`yarn test:runtimes`, 20 checks): Node with no init, `init({ bytes })`, and
  `init({ module })`, each with zero WebAssembly calls at import and one instance; esbuild bundle under `workerd,worker,browser` with no Node builtins, `eval`,
  `new Function`, h3-js, or h3o; no embedded binary in the Worker bundle; `wrangler dev` 4.156.0 / workerd 1.20261023.1 with no
  init (restrictions reproduced); Vite (no init, no WASM request) and webpack (`init({ bytes })`,
  one request) builds in Chromium 156 and Firefox 157. Each runtime matched C on all 34,805 cases.
- Package (`yarn test:package`, 12 checks): 63-file tarball; README example, export map, and the
  fixture probe under Node 24.22.1 (`.nvmrc` and the 24 floor) and 26.12.1 (the 26 floor);
  TypeScript consumer with
  `skipLibCheck: false`; external consumer of the packaged crate plus its 41 tests.
- Benchmarks and memory: `benchmarks/RESULTS.md` (load ≈ 4 on 16 cores, indicative). Faster than
  h3-js on all six priority functions (ratios 0.30–0.90); native Rust within 0.71–1.11× of C with
  identical checksums. WASM memory 1.06 MiB after `init`, plateau 2.13 MiB on repeated workloads;
  workerd backing storage 0.22 MiB (h3-js: a fixed 32 MiB asm.js heap). With no init, the first
  call (compile + instantiate of the embedded binary) took about 2 ms in Node on a quiet machine
  (7 ms at load ≈ 36 in the gate run).

## Deviations from the guide, and open items

- Math libraries (operator decision 2026-11-02, after consulting Fable): native builds use the
  platform libm by default; the `libm` feature routes the six transcendental functions through the
  `libm` crate, and the WASM adapter enables it.
  - Native parity is bit-exact only on linux x86-64 glibc with the default features. Everywhere
    else it holds within the JS bounds; the `native` CI job covers macOS arm64, Linux arm64,
    musl, and Windows.
  - Native with the feature equals WASM bit for bit.
  - `cellsToLinkedMultiPolygon` polygon order is declared unspecified.
  - Cross-libm cell flips near edges, measured with `yarn stress:boundary` (glibc vs `libm`):
    none beyond 1e-15 rad (about 6 nm) from an edge; an estimated 3.5e-13 per random point at
    res 9 and 1.4e-10 at res 15. Fable's pre-measurement estimate (1e-9 and 1e-7) was about four
    orders of magnitude too high. Apple libm not yet measured.

- The clean-checkout gate passed in CI on PR #1 (run 41391165306, ubuntu-24.04, 4 min 55 s),
  including `cargo package` without `--allow-dirty`, runtime tests in Chromium and Firefox, and
  `check:wasm-artifact`.
- The guide's CMake command needed `-DBUILD_FILTERS=ON` at the pinned revision (docs/build.md).
- Initialization is implicit (first-use synchronous instantiation) instead of the guide's required
  awaited `init`; see `docs/api-decisions.md`, "Initialization".
- The private WASM ABI uses reused Rust-owned output buffers and fixed result slots instead of
  returning `Vec`s for most results, based on measured boundary costs (docs/api-decisions.md).
- `wasm/h3.wasm`, its glue, and the embedded module are byte-identical between the development host
  and a GitHub-hosted runner (the build manifest records host paths as placeholders).
- License: MIT (operator decision, 2026-11-02), with the H3-derived portions shipped alongside
  `LICENSE-APACHE-2.0`, `NOTICE`, and `THIRD_PARTY_NOTICES.md` per Apache-2.0 section 4.
- Exact ties in `cellsToMultiPolygon` polygon areas are ordered by Rust's stable sort; C's `qsort`
  order for exact ties is implementation-defined (no tie occurred in the fixtures except the globe
  case, which matched).
- Downstream Mailwoman work is pending and out of scope: the `haversineKm` import-path fix,
  application `init`, consumer migration, and the layer-database cell-column comparison. The
  original geocoder memory problem is not resolved by this library alone.
